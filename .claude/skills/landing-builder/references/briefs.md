# Шаблоны брифов, референс-борда и смысловой структуры

Заполняй шаблоны данными из разговора с пользователем. Неизвестное — спрашивай, но группируй вопросы: один блок вопросов за раз, а не допрос из двадцати пунктов. Очевидное из контекста не переспрашивай — заполни сам и пометь «предположение, поправьте».

---

## Шаблон brief.md (продуктовый бриф)

```markdown
# Продуктовый бриф — [название проекта]

## Продукт
- Что продаём: …
- Сценарий покупки: [увидел рекламу → лендинг → заявка → звонок → оплата / …]
- Цена и как показываем: [открыто / «от…» / по запросу — почему]

## Аудитория
- Кто: …
- Страны проживания (юрисдикция!): …
- Температура трафика: [холодный — не знают продукт / тёплый — сравнивают / горячий — ищут где купить]
  → холодному трафику нужно больше объяснений и доказательств, горячему — короче путь к форме

## Главное действие
- Что должен сделать посетитель: [оставить заявку / записаться / купить / подписаться]
- Лёгкий шаг для сомневающихся (если есть): [получить прайс / задать вопрос]

## Юридически значимые ответы (пойдут в legal-map.md)
- Оплата прямо на сайте: [да → оферта, касса/чеки / нет → оферта не нужна]
- Рассылки и повторные касания клиентов: [да → второй необязательный чекбокс согласия на рекламу / нет — но предупреди: без него писать про акции будет нельзя]
- Особые категории: [медицина / финансы / дети / биометрия / нет] → при «да» — флаг «нужен юрист»

## Доказательства (только реальные)
- Что есть: [кейсы, отзывы, цифры, сертификаты, фото работ]
- Чего нет (не выдумывать!): …

## Оператор данных
- От чьего имени работаем: [физлицо / самозанятый / ИП / ООО / иностранная компания]
- Реквизиты для документов: …

## Форма, CRM, аналитика
- Поля формы (минимум!): [имя + телефон / …]
- CRM: [нет / какая]
- Аналитика: [нет / какая — подключаем только выбранную пользователем и допустимую в юрисдикции]
- Куда слать уведомления о заявках: …

## Инфраструктура
- Домен: [есть какой / нужен]
- Сервер: [есть какой / нужен — страну диктует юрисдикция]

## Сроки и ограничения
- Дедлайн: …
- Ограничения: [бюджет, «нельзя использовать X», технические]
```

## Шаблон design-brief.md (дизайнерский бриф)

```markdown
# Дизайнерский бриф — [название проекта]

## Впечатление
- Какое впечатление должен создавать бренд: …
- Три подходящих определения: [например: уверенный, тёплый, точный]
- Три НЕподходящих: [например: НЕ корпоративный, НЕ игрушечный, НЕ кричащий]

## Фирменный стиль
- Брендбук: [есть/нет, ссылка]
- Логотип: [есть/нет, файлы]
- Цвета: [заданы / выбрать под проект]
- Шрифты: [заданы / выбрать — один шрифт]
- Допустимый фирменный градиент: [какой / выбрать: 2 близких цвета, одно направление]

## Визуальный характер
- Плотность: [воздушно / средне / плотно]
- Стиль фотографий и изображений: [живые фото / предметка / иллюстрации / без образов]
- Доступные реальные материалы: [фото продукта, команды, работ — что есть]

## Конкуренты
- Кто: …
- Как выглядят: …
- Наше визуальное отличие: …

## Мобильные приоритеты
- Что обязательно видно на первом экране телефона: …
- Ожидаемая доля мобильного трафика: …

## Референсы от пользователя
- Нравится: [ссылки + что именно]
- Не нравится (антиреференсы): [ссылки + что именно]
```

## Шаблон reference-board.md (референс-борд)

Собери 3–6 референсов и 2–3 антиреференса. Референсы ищи среди работающих продуктов и качественных лендингов, близких по задаче (не по отрасли — по задаче: «дорого продать услугу», «записать на консультацию»).

```markdown
# Референс-борд — [название проекта]

## Референс 1
- Ссылка/изображение: …
- Что именно нравится: [конкретно: первый экран, подача цены, блок доказательств]
- Какую задачу решает приём: …
- Что переносим: …
- Что НЕ копируем: [контент, логотип, специфичные для их продукта решения]
- Как адаптируем под наш продукт: …

## Референс 2 …N
[та же структура]

## Антиреференс 1
- Ссылка/изображение: …
- Чего именно избегаем и почему: …

## Антиреференс 2 …N
[та же структура]

## Вывод
- Общий паттерн из референсов (что повторяется в большинстве): …
- Главные решения для нашей страницы: …
```

## Шаблон structure.md (смысловая структура)

Составляется ДО дизайна. Каждый блок отвечает на очередной вопрос посетителя. Блок, который не отвечает ни на какой вопрос, — лишний.

```markdown
# Смысловая структура — [название проекта]

Последовательность вопросов посетителя ([температура трафика] трафик):
1. Что это и для кого?
2. Мне это подходит?
3. Почему вам верить?
4. Сколько стоит?
5. Что делать дальше?
[скорректируй под продукт: горячему трафику — короче, холодному — добавь «зачем мне это вообще»]

## Блок 1 — [название]
- Отвечает на вопрос: …
- Функция: …
- Доказательство в блоке: [реальное — из брифа]
- CTA блока: [есть/нет; какой]
- Объём текста: [заголовок + 2 строки / список из N / …]
- Ограничения: [что должно поместиться, чего не должно быть]

## Блок 2 …N
[та же структура]
```
