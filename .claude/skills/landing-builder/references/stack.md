# Техническая сборка: статика + лёгкий бэкенд

Стек по умолчанию. Причина выбора: лендинг — это одна страница и одна форма; фреймворки, сборщики и оркестрация здесь добавляют стоимость и точки отказа, не добавляя ценности. Всё должно чиниться одним человеком по SSH.

## Состав

| Слой | Решение по умолчанию | Когда отступить |
|---|---|---|
| Фронтенд | Статические HTML + CSS + ванильный JS | Никогда для лендинга |
| Бэкенд | Python + FastAPI (или Flask), один файл | Node/Express, если на сервере уже живёт Node |
| База | SQLite, один файл | Postgres — если заявок тысячи в день или несколько приложений |
| Веб-сервер | nginx: статика напрямую, /api — прокси на бэкенд | |
| HTTPS | certbot (Let's Encrypt), автообновление | |
| Процесс | systemd-сервис с автоперезапуском | |
| Уведомления | Telegram-бот: «Новая заявка №N» без ПД | Почта, если у владельца нет Telegram |

## Фронтенд

- Мобильная вёрстка в приоритете: основной трафик лендингов — с телефонов.
- Семантичный HTML, без CSS-фреймворков; системные шрифты или один подключённый локально (не с зарубежного CDN, если юрисдикция РФ, — это передача IP за рубеж).
- Структура страницы: оффер и выгода в первом экране → подтверждение (кейсы, цифры, отзывы) → форма → подвал со ссылками на документы.
- Форма: минимум полей, маска для телефона, состояние загрузки на кнопке, явное сообщение об успехе и об ошибке. Чекбокс согласия — по требованиям юрисдикции.
- Вся страница должна открываться быстро: без каруселей, тяжёлых видео и шрифтов на мегабайты. Проверяй размер страницы — целься в первый экран меньше 500 КБ.

## Бэкенд

Один обработчик `POST /api/lead`:

1. Валидация полей (обязательные заполнены, телефон/e-mail похожи на настоящие).
2. Антиспам без CAPTCHA: скрытое honeypot-поле (заполнено — молча отбрасываем) + ограничение частоты по IP (например, 5 заявок в час). CAPTCHA не ставим — режет конверсию; Google reCAPTCHA в РФ ещё и передаёт данные за рубеж.
3. Запись в SQLite: поля формы, статус `new`, время, IP, версии текстов согласий (обработка и рассылка — отдельными полями), источник заявки (основной оффер / лидмагнит).
4. Уведомление владельцу (без персональных данных клиента).
5. Ответ фронтенду: номер заявки (для «Заявка № N принята») и, если есть лидмагнит, ссылка на него — экран успеха выполняет обещание мгновенно.

Статику локально бэкенд может отдавать сам (удобно для разработки), но монтируй её **условно** — только если каталог существует, а путь бери из переменной окружения с дефолтом. В проде статику отдаёт nginx, каталога рядом с бэкендом нет, и безусловный mount уводит systemd-сервис в бесконечный рестарт-цикл.

Лидмагнит-файл (если есть) клади в статику и выдавай ссылкой на экране успеха. Доставка письмом — только если владелец сознательно выбрал собирать верифицированные адреса; тогда SMTP появляется в архитектуре с первого дня, а не после жалобы «письмо не пришло».

## Админка

Закрытая страница `/admin` за паролем (basic auth в nginx либо сессия в бэкенде; пароль — сгенерированный, не словарный):

- Таблица заявок: имя, контакт, комментарий, время, статус.
- Статусы: новая → в работе → закрыта. Переключение в один клик.
- Фильтр по статусу, выгрузка в CSV.
- Удаление записи (нужно для исполнения запросов на удаление данных).
- Вёрстка админки тоже мобильная: владелец будет открывать её с телефона по уведомлению.

## Деплой

1. Домен → A-запись на сервер (страна сервера — из архитектурного решения по юрисдикции).
2. nginx: статика из каталога, `/api` и `/admin` — прокси на бэкенд; заголовки безопасности (HSTS, X-Content-Type-Options, X-Frame-Options).
3. certbot для HTTPS, проверить автопродление.
4. systemd-сервис для бэкенда, `Restart=always`.
5. Бэкап SQLite: cron-задача, копия раз в сутки в отдельный каталог, хранить 30 копий. В юрисдикциях с локализацией бэкап остаётся на том же сервере или в той же стране.
6. Проверка после деплоя: отправить тестовую заявку с телефона, убедиться, что она видна в админке и уведомление пришло; отправить форму без чекбокса — убедиться, что не уходит; открыть сайт по http — должен быть редирект на https.

## Аналитика

Подключай только после проверки по справочнику юрисдикции (РФ — Яндекс Метрика; ЕС — только после cookie-согласия либо безкуковая аналитика; США — свободнее). Цели настраивай на отправку формы — это единственная метрика, которая важна лендингу.
